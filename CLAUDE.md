# Excel → Word Pivot

Client-side Next.js app. User pastes one or more Excel/Sheets tables; the app restructures each into an Excel-pivot-style **nested hierarchy** ("Rows area"), renders Word-ready HTML, and copies it to the clipboard for pasting into Word.

The problem this solves: wide Excel tables do not fit an 8.5x11 Word page. This app turns one wide table into a narrow, nested outline. You arrange fields into ordered **indent levels** (each level can hold one or more fields stacked at the same indentation); rows nest and merge by those levels. The **title** can **map to the destination document's Heading style** (e.g. `Heading 1`) via `mso-style-name`, so a "Use Destination Styles" paste adopts the template's heading; the **body** always uses the app's own per-level direct styling (Arial 11 default, with per-level bold).

Multiple pasted tables are edited one at a time in a 4-pane **IDE-style layout**: a top command band (brand + section count + **⚙ Document** popover + Clear all / Copy section), a left **Sections rail** (the tables — each its OWN standalone Word document, like independent tabs, NOT stacked sections — **reorderable by drag-and-drop** (grip handle ⋮ + keyboard ↑/↓ as the accessible path) and **duplicable** via a ⧉ button), a center builder, and a pinned right **live preview** (Preview / **Table** / JSON tabs — the **Table** tab shows the raw pasted grid exactly as it came from Excel, before any restructuring; the Preview tab always shows the active section). Heading appearance is a **shared** per-level style applied to every table (edited inline in the per-level matrix's **Look** column, tinted + badged *All tables*), while the document-wide **Body font** / **Indent** / **Reset levels** live in a compact **⚙ Document** popover in that top band; each table keeps its own field choices and title. Export is the per-section **Copy section** (copies only the active section as one standalone Word document; clipboard only — no download), which shows an inline + screen-reader-announced **paste-guidance confirmation** afterward. The whole workspace (every table + config + the shared styling) **auto-saves to `localStorage`** so a refresh doesn't lose work (local-only, nothing uploaded); a first-run **onboarding** empty state (value prop + 1-2-3 steps + **Try an example**) and **paste-anywhere** (Ctrl/Cmd+V drops a table in without focusing the paste zone) speed activation; **Remove section** and **Clear all** are undoable (Clear all is a two-step inline confirm).

## Hard Rules
- SheetJS install is the official CDN tarball: `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`. NEVER install `xlsx` from npm. The npm version is stale (0.18.5).
- Client-side only. No API routes, no backend, no database. Parsing runs in the browser.
- Files at repo root. No `src/` directory. Import alias `@/*` maps to `./*`.
- SheetJS clipboard parse: `getData('text/html')` first, `getData('text/plain')` TSV fallback. Use `sheet_to_json(ws, { header: 1, blankrows: false, defval: "", raw: false })`. Keep `defval: ""` so blank cells stay as empty strings and column positions stay aligned.
- Keep docs in sync with code. When a change alters the pivot behavior, the data model, the pipeline, or a user-facing control, update the affected docs in the SAME change: this `CLAUDE.md` (Architecture / Data Model / Pivot view / Current status), `README.md`, and the relevant `docs/` file (OVERVIEW / ARCHITECTURE / ROADMAP). Stale docs are a bug.

## Data Model
The product is a recursive pivot tree, not a flat table:
- `PivotNode { lines: PivotLine[], children: PivotNode[] }`; `PivotLine { col, name, value }` keeps each field's label `name` (header) and `value` SEPARATE + raw (the renderer escapes/formats them). A node's `lines` are the fields at one indent level (≥1), rendered stacked; the first line carries the level's marker (in **custom** mode) or its app-drawn static number (in **multilevel** mode, which replaces the marker) — and nothing in **off** mode. Rows whose values match across all of a level's fields **merge** (composite group key).
- The pivot structure is `pivotLevels: number[][]` — ordered **indent buckets**; bucket index = indent depth, each bucket a non-empty ordered list of grid columns. Columns in no bucket are unused (hidden).
- `FieldLabel { show, bold, italic, underline }` (per grid column, in `TableState.fieldLabels`) controls each field's label prefix (`name: `): hide it, or bold/italic/underline it. Bold and italic cover the whole `name: `; underline covers only the name (not the `: ` separator). Default = shown, plain.
- `sortDirs: Record<col, "asc"|"desc">` (per grid column, like `fieldLabels`) sorts the sibling groups at that field's level; absent col = off (first-seen). `breakAfter: boolean[]` (per indent level, like `markers`) toggles a blank spacer line after that level's groups. `numbering: { mode: "off"|"custom"|"multilevel"; start: string; levels: boolean[] }` (per table; the **Markers** control) drives the body's marker/number style — **off** = no markers and no numbers (plain rows); **custom** (the DEFAULT) = each level shows its own chosen `markers` symbol; **multilevel** = app-drawn static multilevel numbers. `start` is a dotted-decimal string (the exact number of the first top-level item, e.g. `"5.1"`) and `levels` shows/hides the number per indent level — both apply only in multilevel mode (`NumberingConfig` from `lib/renderers.ts`). `headingLevels: boolean[]` (per indent level) maps a level's rows to a destination **Word heading** (nav pane + collapsible, flush-left); Word supplies their number, so the app number/marker is suppressed on them.
- Two OPTIONAL per-table fields round out `TableState`: `headerRow?: number` (0-based, default 0) — which raw-grid row is the effective header (bump it to skip banner/title rows sitting above the real header; `bodyGrid(t) = t.grid.slice(headerRow)` drops only leading ROWS, so column indices in `pivotLevels`/`fieldLabels`/`sortDirs` stay valid); and `pageBreakBefore?: boolean` (default false) — start each top-level group after the first on a new Word page (renders `data-break` → `page-break-before:always`). BOTH are optional, so old `localStorage` sessions and older `.json` imports remain compatible (every consumer reads them via `?? default`).
- Rendered as a title row (`<p class="ws-title">`) + nested rows (`<p class="ws-lvl" data-level="N">`, a `data-heading="K"` attr on rows the user mapped to a Word heading); `buildWordHtml` maps the title AND any heading-marked levels to Word heading styles, and the rest of the body (markers, app-drawn numbers, spacers) to the app's direct per-level look.

## Pivot view
The one view (`rowsToPivotTree`) replicates Excel's "Rows area" as ordered indent buckets:
- **Add fields** — a pool of the columns not yet placed; clicking one appends it as a new deepest single-field level (once the 9-level cap — `MAX_LEVELS` — is reached it STACKS into the deepest existing level instead of creating a 10th).
- **Structure** — the placed fields as an indented list, drawn with Windows-Explorer-style **tree connector lines** (│ ├ └, via a `rowGuides`/`GuideCell` helper) to show the nesting. Reordering and indenting are entirely via the ◄ ► ▲ ▼ ✕ buttons. Per field: ◄ **outdent** / ► **indent** (set the indent level; stacking fields at one level shows them together and merges by the composite of that level's values), ▲/▼ **reorder** (swap with the flat-order neighbour, keeping the bucket shape), ✕ **remove**, four label toggles — **Aa** (show/hide the `name:` label prefix → "Item Category: Fruit" vs "Fruit"), **B** (bold the label — also bolds that line's leading number/marker), **I** (italicize the label), **U** (underline the label — only the name, not the `: ` separator) — and a **sort** cycle (↕ off / ↑ ascending / ↓ descending) that orders the sibling groups at that field's level. Emphasis targets the label only; the value stays plain. Label look (`fieldLabels`) and sort (`sortDirs`) are both stored per grid column, so they persist across remove/re-add. Depth is capped at **9 levels** (`MAX_LEVELS`, the most Word renders): ► indent is disabled once there are 9 levels, and a live **N/9 levels** chip in the Structure sub-header (muted → amber at 9 → red over 9) plus an at-/over-cap warning enforce it — 9 is the real ceiling because the renderer clamps `data-level` at 9, the preview builds exactly 9 level rules, and `buildWordHtml` only matches `data-level`/`data-heading` 1–9, so the builder can't diverge from the preview/Word output.
- **Sorting** (per field, `sortDirs: Record<col, "asc"|"desc">`) — a post-pass on the built tree reorders the SIBLING groups at a field's indent level by that field's value: one comparator (`localeCompare` with `numeric:true, sensitivity:"base"`) auto-handles numbers and text ("2" before "10", text alphabetical + case-insensitive), reversed for `desc`. Off keeps first-seen order; a stable sort keeps equal-keyed siblings in first-seen order. When a bucket stacks several sorted fields, the first in bucket order wins.
- **Markers** (per-table, `numbering.mode` + `markers: MarkerKind[]` indexed by indent level) — a 3-mode dropdown (**Off (none)** / **Custom (per level)** / **Multilevel numbers**; default **Custom**). In **custom** mode the per-level matrix's Marker/Number column shows a **Marker** `<select>` per level picking its style: `1.` / `1)` / `A.` / `a.` / `I.` / `i.` / `•` / `–` / None (sparse → `defaultMarker(depth)`, the `1./a./i.` cycle); only the FIRST field of a multi-field level is marked and the title is never marked. In **multilevel** mode that column becomes the **Show number** checkbox (see **Numbering**) and a node's marker is suppressed (the number replaces it). In **off** mode the column is hidden entirely and body rows show no marker and no number.
- **Blank line between top-level groups** (per-table, `breakAfter: boolean[]`) — a single on/off checkbox beside the **Markers** control (no longer per-level): on → `breakAfter=[true]`, off → `[]`. When on, the renderer pushes one empty spacer paragraph (nbsp, no marker/number/label) after each top-level group's whole subtree, so the preview and the Word paste show a blank line before the next top-level group (after each title → a gap before the next title). Sibling counting is by node position and spacers are emitted after the subtree, so they never perturb the marker/number counters.
- **New page per group** (per-table, `pageBreakBefore`) — a single on/off checkbox beside the **Blank line** checkbox. When on, the renderer marks the first line of each top-level (depth-1) group AFTER the first with `data-break`, which `buildWordHtml` turns into `page-break-before:always`, so each top-level group starts on a fresh Word page. The preview shows a dashed-rule divider (a page-boundary proxy) before each such group. Independent of the title (depth 1 = the top-level groups whether or not a title exists), and a row can be BOTH a page break and a Word heading.
- **Header row** (per-table, `headerRow`, 0-based, default 0) — a small **Header row** `<select>` in the **Table view** (shown when the grid has ≥3 rows) that skips banner/title rows sitting ABOVE the real header (e.g. a "Q3 Report" banner that would otherwise become the field names). `bodyGrid(t) = t.grid.slice(headerRow)` re-slices the grid for the mapper, the builder's field list, and the page-count stat at once — it drops only leading ROWS, so `pivotLevels`/`fieldLabels`/`sortDirs` (all column-keyed) stay valid.
- **Empty-column drop** (automatic, no UI) — on ingest, `dropEmptyColumns` removes any column whose every cell (header included) is blank/whitespace, so spacer/padding columns never clutter the Add-fields pool or merge as "(blank)". Column order is preserved; a header-only (blank-data) column is kept; a 0-column grid is never produced.
- **Duplicate a section** (per-section) — the rail's **⧉** button deep-clones the section (`structuredClone` under a fresh id, spliced in right after the original and made active; respects the 100-section cap, undoable), for the "several near-identical tables" workflow (same shape, different month/region).
- **Numbering** (the **Multilevel numbers** mode of the Markers control; per-table, `numbering: { mode, start, levels }`) — app-drawn STATIC multilevel numbers (NOT Word auto-numbering). When `mode==="multilevel"`, the renderer (via `multilevelNumbers`) prefixes each node's first line with its number as plain body text. `start` is a dotted-decimal STRING that is the EXACT number of the first top-level item: the top shown level reads it with its LAST component advanced per sibling (`Start "5.1"` → 5.1, 5.2 across top items) and each deeper shown level appends `.<1-based index>` (5.1 → 5.1.1 → 5.1.1.1). So to nest a body under a `5.0` **Section title**, set `Start "5.1"`. The number replaces the marker on that node, and the leading number/marker inherits the field's bold. A per-level **Show number** checkbox (`numbering.levels`, indexed by indent level — the matrix's Marker/Number slot in Multilevel mode) shows/hides each level's number; a hidden level is **transparent** — its line goes plain AND its children CONTINUE the nearest shown level's sequence, so the numbers form a contiguous outline of only the shown levels (number TYPE + TEXT, hide TITLE → `5.1` then `5.1.1`, `5.1.2`… — it *follows* the gap, never a number under a missing parent, and the shared counter across hidden siblings means no collisions). `start` is a free dotted decimal (digits + dots); numeric only for now (the marker code is structured so letter/roman styles could be added later). The numbers themselves never make a row a Word heading (see **Word heading** below for that); the preview shows the real numbers verbatim.
- **Word heading** (per-table, `headingLevels: boolean[]`, per indent level, the per-level matrix's **Word heading** checkbox column) — map a level's rows to a destination `Heading K` style (K = `titleLevel + depth`, clamped 9, so under a `Heading 1` title the top body level → `Heading 2`, and under a `Heading 3` title → `Heading 4` — Heading 2/3/4 titles now nest their body headings correctly). On a **Use Destination Styles** paste those rows enter the document outline — **Navigation pane + collapsible**, flush-left (they lose the body indent) — and **Word supplies their number**, so the app's number/marker is suppressed on them. A heading level still establishes a numbered BASE, so deeper app-numbered rows nest AND **reset under each heading group**: TYPE → Word `5.1`/`5.2`, its TITLEs → app `5.1.1`/`5.1.2`, then `5.2.1` under the next type. Set **Start** to the heading's section number (e.g. `5.1`) so the app's deeper numbers line up with Word's heading number. Use it on just the top level or two, so the nav gets a few useful entries (not a flood). The preview shows those rows flush-left + bold with a `#` placeholder for Word's number.
- **Look** (per DEPTH, GLOBAL — the per-level matrix's **Look** column) — each level row's inline color swatch + an **Aa** button that opens a small popover with **Font / Size / Bold** sets that depth's body-row look. The column is tinted + labeled *all tables, by depth* to signal it is shared across every section (unlike the per-table Marker / Heading columns); the depth slot it edits follows the renderer (`bucket + (sectionTitle ? 1 : 0)`). See **Styling** for the shared state.
- **Section title** (optional) — the level-0 title row (`MsoTitle`), edited in its own **Section Header** control group (title text + a global **Heading** dropdown `None / Heading 1–4` + a shared **title look** — font/size/color/bold/italic/underline). Pick a Heading and it maps to that real Word heading at the chosen outline level (`mso-outline-level:<N>`, one Nav-pane entry per table; Heading 1–4 each produce a correct, consistent outline) — the mapped title emits its FULL shared Look (font/size/color/bold/italic/underline) inline, so it pastes EXACTLY as the preview shows; Word supplies only the heading's auto-number + outline/nav entry + paragraph spacing + any all-caps effect; **None** renders it with the full shared title look (`HeadingStyle.titleStyle`), NOT the level chart. With a title the nested data starts at level 2; without one, level 1. Numbering is independent of the title (top data siblings number from `start` whether or not a title exists; the title is never numbered).

## Styling
**Title → Word heading mapping:** the per-section **Heading** dropdown (default `Heading 1`; options `None / Heading 1–4`, in the Section Header group) maps ONLY the title via `mso-style-name`+`mso-outline-level:<N>` (the chosen heading number, so Heading 1–4 each produce a correct, consistent Word outline). On a **Use Destination Styles** paste the mapped title emits its FULL shared Look — font/size/color/bold/italic/underline — inline (one `<span>` + `<i>`/`<u>` runs, with an explicit `font-weight` that bolds OR un-bolds an intrinsically-bold heading), so it pastes EXACTLY as the live preview shows; Word supplies only the heading's auto-number, its outline/nav-pane entry, its paragraph spacing, and any all-caps font effect (the two things inline HTML cannot override while mapped); **None** = the title's own shared direct look in full (`HeadingStyle.titleStyle`: font/size/color/bold/italic/underline). That is one Nav-pane entry per table. **Body rows are mapped only when you mark a level as a Word heading** (then `data-heading="K"` → `Heading K`, so those rows enter the nav pane + collapse); every other body row (markers, app-drawn multilevel numbers, spacers) uses the app's per-level look, emitted inline (so it survives the paste and matches the live preview), with per-field label `<b>`/`<i>`/`<u>` runs on top. App-drawn multilevel numbers are plain body text, so an un-marked body never becomes a Word heading and Word's Nav pane / TOC stay clean.

One **shared per-level** look ("Level styles") drives the **nested body rows** across all tables — `HeadingStyle = { levels: LevelStyle[]; indentStep: number; headingStyleName; titleStyle }`. Each depth's color/font/size/bold is edited inline in the per-level **matrix's Look column** — an inline color swatch plus an **Aa** button that opens a small popover with **Font / Size / Bold** — tinted + labeled *all tables, by depth* to set it apart from the per-table Marker / Heading columns; **defaults are plain Arial 11 black** (to match a document body), with a "Reset levels" button in the ⚙ Document popover. The **title is no longer in this chart** — it has its own shared look (`titleStyle`, set in the Section Header group); the level chart styles the nested rows by depth (`data-level` N; Level 1 applies to the top body row only when there is no Section title). Each matrix row edits the global level-style slot `bucket + (sectionTitle ? 1 : 0)` (matching the renderer's `walk(nodes, 2, 1)` so preview and Word export stay in sync). The document-wide **Body font** control (document body font) and **Indent/level (in)** control (`indentStep`, clamped 0–2; nested rows indent `(n-1)×step`), plus Reset levels, live in a compact **⚙ Document** popover (badged *All tables*) in the top command band — driven directly by `PasteInput` (they are no longer in the center builder or the `appearance` bundle, which now carries only `{ levelStyles, onLevelChange }`). The state stays GLOBAL by depth (owned by `PasteInput`) — only the editor UI location changed. Body paragraphs use compact spacing (`line-height:115%`, no space before/after). All style inputs are form-controlled (hex color, allow-listed font, clamped numbers), so no free user text lands in a `style`/`class` attribute.
