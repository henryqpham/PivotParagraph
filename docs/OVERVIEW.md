# Overview

## What this is

**PivotParagraph** — a web app that converts **pasted Excel data into a Word-ready nested outline**. You paste one or more tables copied from Excel (or Google Sheets); the app restructures each into an Excel-pivot-style hierarchy ("Rows area") and copies it to the clipboard so it pastes into Microsoft Word.

## The problem it solves

Wide Excel tables do not fit on an 8.5" x 11" Word page and become unreadable once columns bleed off the right edge. Instead of shrinking or splitting the grid, this app **restructures** spreadsheet data into a narrow, nested outline — you arrange fields into ordered indent levels (each level can stack several fields at the same indentation), and rows nest and merge by those levels — so it flows down a Word page instead of off the side.

## Tech stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **SheetJS** (`xlsx`, official CDN tarball) for parsing clipboard / Excel data
- **Tailwind CSS** (v4) for styling
- **Vite** + `vite-plugin-singlefile` — a *second*, build-time-only target that emits the whole app as one self-contained `.html`
- **Client-side only** — no backend, no API routes, no database. All parsing runs in the browser; nothing is uploaded. The workspace is saved to the browser's own `localStorage` (on your machine only) so it survives a refresh.

## Two ways to run it

Because the app is 100% client-side, the same `components/` + `lib/` code ships two ways:

1. **`npm run dev` / `npm run build`** — the Next.js app (the development path).
2. **`npm run build:single`** — one self-contained `dist-single/index.html` (~660 KB) with every asset inlined and **zero external requests**. It runs from a `file://` double-click, so it can be shared on a network drive with no hosting or install. See [ARCHITECTURE.md](./ARCHITECTURE.md#single-file-build) for the `file://`-specific build choices.

## What works today

The full pivot pipeline is implemented end to end, for multiple tables:

1. **Add → parse.** Tables are added through a focused **＋ Add table** modal (a persistent button in the top command band, a big "Add a table" hero in the onboarding empty state, and an "Add another table" strip above the builder). It runs in two phases: **intake** — a dashed drop well that accepts a **paste** (a window paste listener while the modal is open), a **file drop / Browse** (`.xlsx` / `.xls` / `.csv` / `.tsv`), and a **Try an example** link — then a **preview** ("✓ Read N rows × M columns" + a mini-table) with **Add section** / **Clear**, so a mis-copy (a stray cell, a non-table selection) is caught before it becomes a section. Files are read fully client-side by `parseFile` (`XLSX.read(await file.arrayBuffer(), { type: "array" })` — the same already-installed SheetJS, first sheet, identical `sheet_to_json` options via a shared `firstSheetToGrid` helper). A copied table also still drops in on **Ctrl/Cmd + V from anywhere** on the page (unless a text field is focused, or the modal is open — it owns paste then, and `PasteInput`'s global listener bails via `addModalOpenRef` so there's no double-ingest). Every path funnels through one `ingestGrid`: fully-blank spacer columns are dropped (`dropEmptyColumns`) so they never clutter the field pool, then a new table is appended. If the new table's **headers match an already-arranged section**, a banner offers to **reuse that section's arrangement** (levels, markers, headings, labels, sort) in one click — the recurring-report workflow (same table shape, new month's data) without rebuilding the outline; otherwise **Smart Arrange** (`lib/smartArrange.ts`) proposes a nested outline from the column shapes so the paste lands already-structured, with a dismissible **"Auto-arranged into N levels — Start blank"** banner (an exact-header reuse match takes precedence; both paths are one undo step). Tables are managed in a left Sections rail (one edited at a time, cap 100, **reorderable by drag-and-drop** — a grip ⋮ + keyboard ↑/↓ — and **duplicable** via a ⧉ button for near-identical tables; each section is its own standalone Word document) within a 4-pane IDE layout — top global controls, left rail, center builder, and a pinned right live preview. A first-run **onboarding** empty state (value prop + 1-2-3 steps + the **Add a table** hero) gets a newcomer started with no spreadsheet; **every change is undoable and redoable** (Ctrl+Z / Ctrl+Y, persistent toolbar buttons; Clear all is a two-step inline confirm), and the whole workspace **auto-saves to the browser's `localStorage`** so a refresh doesn't lose it. A **Ctrl/Cmd + K command palette** (`components/CommandPalette.tsx`, a "⌕" button in the top band) is a fuzzy launcher over every action — Add table, Copy section, Duplicate/Remove section, Undo/Redo, Document settings, Clear all, and a "Go to section" entry per table.
2. **Nest → tree.** `rowsToPivotTree` nests rows by an ordered list of **indent buckets** (`pivotLevels`) into a recursive `PivotNode` tree. The builder caps indent depth at **9 levels** (`MAX_LEVELS`, the most Word renders), so a field added past the cap stacks into the deepest level instead of making a 10th. Each bucket is one indent level holding one or more fields; fields stacked in a bucket render at the same indent and rows merge by the composite of that level's values.
3. **Render → preview.** The tree is rendered to HTML and shown in the pinned right-pane live preview on a **true-to-scale US-Letter page proxy** — a proportional 1in-margin frame (so text wraps in a ~6.5in column, close to how it flows in Word) with **measured, best-effort pagination**: a ref + `ResizeObserver` measure the paper width and rendered content height, and a dashed **"Page N"** boundary is drawn every 9in usable band, with a green **Fits 1 page** / amber **~N pages (estimate)** chip and an honest **"Showing: your Keep-Source look"** label (a Use-Destination-Styles paste instead adopts your template's own Heading styles). This is explicitly an **estimate** — Word wraps in the destination font, so a real break can shift a line or two; the app does not claim pixel-exact parity, and the `tableToHtml` → `renderPivotTree` pipeline (with the scoped per-level `<style>`) is untouched — the page proxy is a layout wrapper only. A **Table** tab beside the preview shows the raw pasted grid as an actual table; the Preview tab always shows the active section you're editing. (There were once four view modes and a raw-JSON tab; both were cut — the JSON view earned nothing a developer couldn't get from devtools.)

The builder itself is split into **three cards by SCOPE**, which is what keeps it legible:

- **Section Title** — the title text, its Word-heading dropdown, and its Look.
- **Rows** (per FIELD) — the Add-fields pool plus one row per field, drawn with Windows-Explorer-style tree connector lines (│ ├ └) to show the nesting. Arranged entirely with **◄** outdent / **►** indent / **▲ ▼** reorder / **✕** remove; the changed row **briefly highlights** (accent tint ~1.1s, re-armed on each click so a burst reads as one continuous highlight, and skipped under `prefers-reduced-motion`) so a field is easy to follow as it moves. *(Drag-and-drop was built here and deliberately reverted: the arrow buttons read as more intuitive and are keyboard-accessible for free.)* Each field name renders as a **live micro-preview in its level's real look** with a faint sample value from the first data row. Per field you can hide/bold/italic/underline the `Field name:` label — these touch **only** the label, the text before the colon — and **sort** the groups at that field (↕ off / ↑ asc / ↓ desc, numeric + text aware). A stacked sibling shows a muted "shares level N" note.
- **Level formatting** (per LEVEL) — the per-table **Markers** mode plus the two group-layout checkboxes (**Blank line between top-level groups**; **New page per group**, a `page-break-before` that carries into the paste, shown as a dashed rule in the preview), then one compact row per indent level with columns **Level | Marker | Heading | Look · all tables**. Scope is mixed on purpose and marked per column: Marker and Heading are per-table, while the **Look is shared by DEPTH across every section**. The Marker cell is a **Type** select `1/a/A/i/I/•/–/None` × an **After** delimiter select `./)/None` (delimiter disabled for symbol types) in **Custom** mode, a **Show number** checkbox in **Multilevel**, and hidden in **Off**; on a heading-mapped level it reads *Word numbers* instead, since Word supplies that number. The **Heading** cell is a checkbox plus a **rank chip-dropdown** — **Auto** keeps checked levels contiguous so the outline never skips a rank, or pin **H1–H9** for templates whose numbering needs a specific rank (amber-tinted if a pin skips one). The **Look** cell is a color swatch + an **Aa▾** popover (font / size / **B** / **I** / **U**) — the same control the Section title uses — and it restyles the **whole line** (label *and* value), unlike the Rows card's label-only emphasis.
4. **Copy section.** The **Copy section** button (or **Ctrl/Cmd + Enter** from anywhere — the mouse-free way out, pairing with paste-anywhere's way in) exports the active section as its own standalone Word document, writing `text/html` (+ a `text/plain` fallback) to the clipboard (no download) via `writeRichClipboard` — which tries the async Clipboard API and falls back to the legacy `execCommand("copy")` route, so Copy still works where the modern API is refused (notably the single-file build opened from `file://`, an insecure origin). It then shows an inline + screen-reader-announced **Section copied.** confirmation of which Word paste option to pick (**Use Destination Styles** to adopt the document's Heading styles when headings are mapped, or **Keep Source Formatting** to keep your look; avoid *Merge Formatting*, which strips the heading mapping). The **Section title** maps to your document's chosen Heading 1–4 ("5.0") at the right outline level: on a *Use Destination Styles* (or default Ctrl+V) paste it takes the **document's own heading look** plus its number and nav-pane entry, and on a *Keep Source Formatting* paste it keeps **exactly the preview look** you styled (font, size, color, bold, italic, underline). A per-table **Markers** control (a 3-mode dropdown — **Off (none)** = no markers or numbers / **Custom (per level)** = each level's chosen symbol / **Multilevel numbers**; default Custom) sets the body's marker style; the Multilevel mode draws static **multilevel numbers** from a chosen **Start** (the exact first number, e.g. `5.1` → `5.1`, `5.1.1`, `5.1.1.1`) as plain body text — not Word auto-numbering, so nothing becomes a Word heading and the numbers show in the preview verbatim (with a per-level toggle to hide levels; hidden levels are transparent, so the numbers follow the gap). Body rows are styled body text unless you mark their level as a **Word heading**.

**Styling.** The shared per-depth body look lives in the **Level formatting** card's **Look** column — a color swatch plus an **Aa▾** popover (font / size / **B** / **I** / **U**) per depth, badged *all tables* so it applies to every section, and it's the *identical* control (one `LookControl` component) that styles the Section title, so the two areas read as one system — while the document-wide **Body font**, **Line spacing** (Single / 1.15 / 1.5), **Label separator** (`Name: Value`, `Name — Value`, …), **Indent/level**, and **Reset levels** sit in a compact **⚙ Document** popover in the top command band. Every level's font **follows the Body font by default** (change it once and the whole body — preview and paste — follows); a level's Look popover can pin a specific font, and its "Body font (…)" option un-pins it. Both the Look and Document popovers share one dependency-free `Popover` component. The **Section title** and any level whose **Word heading** checkbox is on map to real Word headings — emitted as actual `<h1>`–`<h6>` elements, so they adopt the destination's Heading styles in a brand-new blank document as well as a styled template; the rest of the body — including any app-drawn multilevel numbers — stays out of Word's outline.

## Out of scope

- **`.docx` generation** — export is HTML-on-clipboard only ("Copy section"). There is no download.
