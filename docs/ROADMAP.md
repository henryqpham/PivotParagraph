# Roadmap

The app is **pivot-only**: paste → nest → render → **Copy section**. It began with four view modes and a Download option; those were removed to focus on the pivot. Status of the current feature set below.

| Step | What | Status |
| ---- | ---- | ------ |
| **Data model** | `PivotNode { lines: PivotLine[], children }`, `PivotLine { col, name, value }`, `FieldLabel` ([`lib/types.ts`](../lib/types.ts)) | Done |
| **Paste → raw rows** | SheetJS clipboard parse ([`lib/parser.ts`](../lib/parser.ts)); the raw grid is inspectable in the **Table** view | Done |
| **Pivot mapper** | `rowsToPivotTree(rows, levels, sortDirs?)` — ordered indent buckets; each bucket is one level of ≥1 field merged by a composite key; a post-pass reorders sibling groups per `sortDirs` ([`lib/mapper.ts`](../lib/mapper.ts)) | Done |
| **Structure picker** | Add-fields pool + the **Rows** canvas (one row per field; Windows-Explorer-style tree connector lines │ ├ └ to show nesting), arranged entirely with ◀ outdent / ▶ indent / ▲ ▼ reorder / ✕ remove buttons (`pivotLevels: number[][]`) | Done |
| **Depth cap (9 levels)** | The builder caps indent depth at `MAX_LEVELS = 9` (the most Word renders): `canIndent` requires `levels.length < 9`, and `addField` stacks a new field into the deepest level past the cap; a live **N/9 levels** chip (muted → amber at 9 → red over 9) + at-/over-cap warning in the Structure sub-header. 9 is the real ceiling — the renderer clamps `data-level` at 9, `RenderedPreview` builds 9 level rules, and `buildWordHtml` matches only `data-level`/`data-heading` 1–9, so the builder can't diverge from the preview/Word output | Done |
| **Per-field label format** | Per-field toggles (`fieldLabels`): show/hide the `Field name:` label, bold it, underline it (label-only emphasis) | Done |
| **Per-column sorting** | Per-field ↕/↑/↓ cycle (`sortDirs: Record<col, "asc"|"desc">`) orders the sibling groups at that field's level; numeric + text aware, case-insensitive (`localeCompare`, `numeric:true`); off keeps first-seen order | Done |
| **Markers** | A 3-mode dropdown (**Off** = none / **Custom** = per-level **Type** select (`1/a/A/i/I/•/–/None`) × a FREE-TEXT separator (any string ≤20 chars — `.` `)` `:` `;` `--`; escaped; was a closed `./)/none` select, opened up on mentor feedback; legacy tokens migrate on read) — the separator disables for symbol types / **Multilevel numbers**; default **Off** — a fresh paste carries no preset formatting (was Custom; changed on mentor feedback)); stored as `markerSpecs: {type, delim}[]`, migrated on read from the legacy fused `markers: MarkerKind[]` via `resolveMarkerSpecs`; in Custom the first field of a multi-field level is marked, restarting per parent | Done |
| **Line breaks (before / after / between stacked)** | Positional semantics, reworked after user testing showed the original pair was broken in practice ("before" and "after" looked identical on the deepest level; "after" silently no-opped on one-group-per-parent levels): **Line break before** (`breakAfter: boolean[]`, level-indexed — historical name) = a blank line right BEFORE that level's line(s); **Line break after** (`gapAfter: boolean[]`) = a blank after the level's WHOLE subtree, every group including a sole child; stacked sibling sub-rows add a per-FIELD **Line break before** (`fieldBreakBefore: Record<col, boolean>`) between the stacked lines inside a group (`1.1 Country` → blank → `Product`). A renderer post-pass collapses adjacent blanks and trims both document edges so the options compose without doubling; all three carried by the style preset (`breaksByLevel` projection) | Done |
| **Title heading** | Optional Section title → the chosen Word `Heading 1–4` at the correct outline level, emitted as a real `<hN>` element with a full declared source look (adopts the destination heading cleanly in blank docs AND templates on a Use-Destination-Styles/default paste; level threaded as `titleLevel` via `headingLevel(name)`; a non-built-in style name falls back to the `mso-style-name` class route, now first-class via the dropdown's **Custom style…** text input — map the title to any destination style, e.g. `TBL_TITLE`); the title's font/size/color ride inline and its weight lives in its style rule (no inline `font-weight` — bold is an OOXML toggle and the old inverted trick pasted backwards under KSF), so a Keep-Source-Formatting paste matches the preview exactly while a Use-Destination-Styles paste takes the destination heading's complete look + number/outline (COM-verified) | Done |
| **Multilevel numbering (app-drawn static numbers)** | Per-table `numbering: { mode, start, levels }` (the Markers control's **Multilevel** mode; `mode: "off"|"custom"|"multilevel"`) prefixes each node's first line with a static number from a chosen `start` (a dotted-decimal string = the exact first item number; `5.1` → `5.1.1` → `5.1.1.1`) as plain body text and suppresses that node's marker; a per-level checkbox (`numbering.levels`) hides a level and makes it transparent, so the numbers follow the gap (`5.1` → `5.1.1`, `5.1.2`) with no gaps or collisions; (a per-line "number each stacked field" variant was built and REVERTED same-day — misaligned numbers read worse than the hanging indent that replaced it). NOT Word auto-numbering — nothing becomes a Word heading, so the Nav pane / TOC stay clean and the preview shows the real numbers | Done |
| **Word heading rows** | `headingLevels: boolean[]` (per level, labelled by field name) maps a level's rows to a destination `Heading K` style — emitted as real `<hK>` elements (K ≤ 6) whose rule declares the level's full look, so a Use-Destination-Styles/default paste adopts the destination heading cleanly (blank docs AND templates) and a Keep-Source-Formatting paste shows the preview's bold heading look (KSF never maps named styles); nav pane + collapsible, flush-left; Word numbers them so the app number/marker is suppressed there (the path still computes, so deeper rows nest). K is contiguous by default (checked levels rank in order under the title — no skipped ranks) with an optional per-level pin (`headingRanks`, Auto/H1–H9 chip-dropdown, amber when a pick skips a rank). Scoped to the top level or two, so the nav stays clean | Done |
| **Renderer** | `renderPivotTree(nodes, title?, markers?, fieldLabels?, breakAfter?, numbering?, headingLevels?, titleLevel?, pageBreakBefore?, headingRanks?, labelSeps?, gapAfter?, fieldLooks?, breakBeforeSlots?)` → HTML fragment ([`lib/renderers.ts`](../lib/renderers.ts)) | Done |
| **New page per group** | A per-table `pageBreakBefore` checkbox beside the Markers control starts each top-level group (after the first) on a new Word page: the renderer marks that group's first line `data-break="1"`, `buildWordHtml` emits `page-break-before:always` (inline, so it survives a Use-Destination-Styles paste; also works when the row is a Word heading), and `RenderedPreview` shows a dashed page-break rule | Done |
| **Ingest cleanup** | `dropEmptyColumns(grid)` strips fully-blank spacer/padding columns on paste (automatic, no UI) before `newTable`, so they never clutter the Add-fields pool; a header-only (blank-data) column is kept | Done |
| **Header row offset** | Optional `TableState.headerRow` + `bodyGrid(t) = grid.slice(headerRow)` (used by the mapper, the field list, and the page-count stat) skips banner/title rows above the real header. The in-view **Header row** select was REMOVED by request — the field survives as legacy (a stored offset is still honored on read; there is no UI to set it) | Removed (UI) |
| **Copy shortcut** | **Ctrl/Cmd+Enter** copies the active section from anywhere (pairs with paste-anywhere); the level owner's Heading rank chip-dropdown shows the resulting **H1/H2… chip** and a *Word numbers* note replaces a heading level's marker control | Done |
| **Clipboard output** | `text/html` (+ `text/plain`) for Word ([`lib/clipboard.ts`](../lib/clipboard.ts) `buildWordHtml`) | Done |
| **Multiple tables + Sections rail** | Paste appends a table; rows in a left Sections rail within a 4-pane IDE layout (cap 100) | Done |
| **Duplicate a section** | `duplicateTable(id)` deep-clones a section (`structuredClone`, fresh id) right after the original and makes it active — for several near-identical tables (same headers, different month/region); a hover **⧉** button on each rail row (`SectionsRail` `onDuplicate`) | Done |
| **Shared per-level styling** | The per-depth nested-row look (color swatch + an **Aa▾** popover: font / size / **B** / **I** / **U**) is edited inline in the Rows canvas's **Look** control on each level's first field (global by depth, badged *All tables*) via the shared `LookControl` component — the IDENTICAL control that styles the Section Title, so "the same thing looks the same"; italic/underline emit as `<i>`/`<u>` runs on the body `<p>`. Only the document-wide **Line spacing** and **Reset levels** (+ the **Style preset**) sit in a compact **⚙ Document** popover in the top command band (the Body font, Label separator, and Indent/level controls were all later removed — font fixed to Aptos, separators went per-field, indentation is derived from the outline geometry); a shared dependency-free `Popover` (`components/Popover.tsx`) backs both the Look and Document popovers. `PasteInput` owns the state, passes a slimmed `appearance` prop (`{ levelStyles, onLevelChange, bodyFont }`) → `HeadingStyle = { levels: LevelStyle[] }` (per-depth look, color/font/size/bold each) + one Body font + indent step, and drives body font / indent / reset itself; an untouched level's font INHERITS the Body font (`""` = inherit, Look popover pins), so the Body font control actually drives the body in both preview and paste; the popover also carries **Line spacing** (`HeadingStyle.lineSpacing`, 1/1.15/1.5 → `line-height:N%` in preview + paste) and the **Label separator** (`labelSep`, allow-listed, threads `tableToHtml → renderPivotTree → wrapLabel`); `LevelInput`/`DEFAULT_LEVEL` in `tableModel.ts`, `FONTS` exported from `TableCard` | Done |
| **Per-section export** | **Copy section** — copies the active section as its OWN standalone Word doc (clipboard `text/html` + `text/plain`); sections are independent documents, not stacked. (Replaced the old combined "Copy all".) | Done |
| **Malformed-paste handling** | Graceful empty/parse-error states | Done |
| **Session persistence** | The whole workspace (every `TableState` + shared styling) auto-saves to `localStorage` (versioned key, [`lib/persistence.ts`](../lib/persistence.ts)) — debounced + flushed on tab-hide, rehydrated on mount (id counter re-seeded). Local-only; nothing uploaded | Done |
| **Live preview** | The pinned right pane always previews the **active section** — the same `tableToHtml` fragment Copy section writes, so preview and export can't diverge. *(The former This section / All sections combined-preview toggle was removed along with combined export; `RenderedPreview` still accepts a `sections?: string[]` prop but the app no longer passes it.)* | Done |
| **Copy-section confirmation** | After **Copy section**, a visible + `aria-live` banner reads **Section copied.** and the decisive Word paste step (**Keep Source Formatting** vs **Use Destination Styles**, the latter only when a heading is mapped); friendly failure + “add fields first” states | Done |
| **Reorder sections** | **Drag-and-drop** rows in the Sections rail ([`components/SectionsRail.tsx`](../components/SectionsRail.tsx); native HTML5 DnD, with a grip ⋮ + keyboard ↑/↓ as the accessible path) — `onReorder(from, to)` splice-moves `tables[]` (handler `moveTable`). Each section is its own standalone Word document | Done |
| **Undo / redo (all changes)** | Full workspace undo/redo — an effect observes the `SessionSnapshot` memo and records a step on any meaningful change (all fields except pure `activeId` selection), coalescing rapid bursts (typing, color-drag) via a short debounce; two-stack model with `Ctrl+Z` / `Ctrl+Y` and persistent toolbar buttons. Covers reorder, fonts, bold, indent, markers, title, add/remove/duplicate/clear/import. **Clear all** is still a two-step inline confirm | Done |
| **First-run activation** | Onboarding empty state (value prop + 1-2-3 steps; the rail's **＋ Add section** opens the intake modal, whose Try-an-example loads `makeExampleTable`) and **paste-anywhere** (a window `paste` listener ingests a copied table unless a text field is focused, so nothing needs focus) | Done |
| **Three-card builder (Section / Fields & Title / Body Text Definition)** | `TableCard` is split by SCOPE, which is what makes the two kinds of formatting legible: **Fields & Title Definition** is per FIELD (one row per field, tree connector lines, label Aa/B/I/U touching ONLY the text before the colon, sort, and ◀ ▶ ▲ ▼ ✕), while **Body Text Definition** is per LEVEL (Markers mode + group-layout checkboxes, then a compact matrix: Level \| Marker \| Line break before/after \| Heading \| Look·all tables — a level's Look restyles the WHOLE line). Card headers renamed + accent-tinted on mentor feedback (were Section Title / Rows / Level formatting; the spacer columns were Blank line / Gap after). Every control stays visible (no progressive disclosure) so 9 levels still fit on screen. Field names are plain UI text (a styled live micro-preview + sample value was tried and removed as noise); a stacked sibling shows a blank number pill (tree guides carry the nesting). Level styles stay GLOBAL-by-depth (badged) | Done |
| **Row-change highlight** | Any structural change (◀ ▶ ▲ ▼, or adding a field) briefly tints the affected row (`flashRow`/`applyMove`, ~1.1s, timer re-armed per change so a burst reads as ONE continuous highlight; inert under `prefers-reduced-motion`) — reordering shifts a row out from under the cursor, which otherwise loses the field | Done |
| **Single-file build** | `npm run build:single` (Vite + `vite-plugin-singlefile`) emits ONE self-contained `dist-single/index.html` (~660 KB, zero external requests) that runs from a `file://` double-click — shareable on a network drive with no hosting. Root `index.html`/`main.tsx`/`vite.config.ts`; Next.js is untouched and remains the dev path. Two `file://`-specific choices: an **IIFE** bundle + stripping `type="module"` (module scripts fail an opaque-origin CORS check), and a `DOMContentLoaded` guard in `main.tsx` (a classic script in `<head>` runs BEFORE `#root` exists — the blank-page bug the first build shipped with). Tailwind reuses the existing `postcss.config.mjs`; build-time deps only | Done |
| **Clipboard fallback** | `writeRichClipboard(html, plain)` tries the async Clipboard API, then falls back to `execCommand("copy")` + a capture-phase copy listener that still places real HTML (not just text). The async API needs a secure context, and a `file://` page (origin `null`) is exactly where it gets refused — Copy is the whole payoff, so it can't depend on one API | Done |
| **Add-table modal + client-side file ingest** | A ＋ Add-table modal ([`components/AddTableModal.tsx`](../components/AddTableModal.tsx)) previews what it read before committing: **intake** (paste / file drop / Browse `.xlsx`·`.xls`·`.csv`·`.tsv` / Try-an-example) → **preview** ("Read N × M" + mini-table + Add section / Clear). Files parse fully client-side via `parseFile` (`XLSX.read(arrayBuffer, { type: "array" })`, the same SheetJS, shared `firstSheetToGrid` helper) — no new dependency. `onCommit(grid)` routes to the existing `ingestGrid`; retires the old inert `pasteZone`; paste-anywhere still works (the modal's window listener + `addModalOpenRef` guard prevent double-ingest) | Done |
| **Style preset (export/import the "parser config")** | `lib/stylePreset.ts` + ⚙ Document → **Style preset** Export/Import (and two Ctrl+K commands): saves the FORMATTING alone — global looks/fonts/title + the active section's LEVEL-indexed markers/numbering/headings/blank lines + the Rows-card label emphasis projected BY LEVEL (`labelsByLevel`, re-applied positionally via `applyLabelsByLevel`) — as a versioned `.json`, replayable on any future document. Import applies globals + every section's level-keyed settings in ONE undo step; never touches grids, structure, or per-column settings. Envelope-gated (`kind: "style-preset"`) so a workspace backup can't be fed in; lenient field reads so partial presets load | Done |
| **Add-section in the rail** | The ＋ button lives pinned atop the left Sections rail (the layers-panel convention — sections are made where they live); the top-band button, the in-body "Add another table" strip, and the empty-state hero were all removed as confusing duplicates (mentor feedback) — the rail button is THE add affordance. Paste-anywhere and the palette command remain | Done |
| **Opt-in drag-to-reorder rows** | A **Drag to reorder** toggle switch in the Rows card's top-right (default OFF; a persisted UI preference excluded from undo history — it started in ⚙ and moved onto the card, where it acts) adds a ⋮ grip to each Rows row and hides ▲ ▼ while on (the grip replaces exactly that job). **Vertical-only by construction**: `reorderField(levels, from, to)` splices the flat field order back into the SAME bucket shape, so a drop reorders across many rows in one motion but can never indent/outdent/stack (◀ ▶ remain the only level controls); drop-indicator line + the standard row flash; arrows always work | Done |
| **Version badge + one app-wide font** | A fixed bottom-right `v1.<commit count>` badge (hash in the tooltip), computed at BUILD time from git by `appVersion.ts` and inlined by both build configs — auto-bumps every commit, needs no git at runtime, falls back to "dev" outside a checkout. The UI chrome font stack now LEADS with Aptos, so builder, preview, and Word output share one typeface | Done |
| **Per-field sub-rows + hanging alignment** | Body Text Definition shows one SUB-ROW per field (`2.1`/`2.2` pills on stacked levels, matching the Fields card): Marker/line-breaks/Heading stay level-scoped on the first sub-row; **Label sep** became PER FIELD (`labelSepByCol`, free text ≤20); EVERY sub-row of a stacked level is that field's PER-FIELD **Look** (`fieldLooks` → an inline styled run tagged `data-flook`, this section only; the level look stays on single-field rows — user feedback: "3.1's Look changed all 3") and a field look is AUTHORITATIVE for its line (`data-flook` suppresses the level B/I/U in preview + paste, so per-field can also remove emphasis). EVERY numbered/markered line renders with a real hanging indent (`data-hang`/`data-cont`) sized to the lead's MEASURED width (`ws-lead` span; canvas-measured in the clipboard, DOM-measured pre-paint in the preview, per-glyph estimate headless), and indentation is DERIVED from the outline geometry — each level nests at its parent's TEXT position, 0.25in steps for lead-less levels, `1.1.1` exactly under the parent's text like Word's own multilevel lists (mock-driven request); the ⚙ Indent-per-level control was removed with it. Presets carry `sepsByLevel`/`looksByLevel` projections | Done |
| **Aptos default** | Every font default (Body font, title, preview/clipboard fallbacks) is **Aptos 11** — Microsoft 365's current standard font — so pasted output reads like a native document (mentor feedback; the default walked Arial → Calibri → Aptos). Aptos heads the allow-list; Arial/Calibri remain. Saved sessions keep whatever font they stored | Done |
| **Living Word-page preview** | `RenderedPreview` renders on a true-to-scale US-Letter proxy — a proportional 1in-margin frame (~6.5in text column) with MEASURED, best-effort pagination (ref + `ResizeObserver` → a dashed "Page N" boundary every 9in usable band; the page-fit chip that sat above the paper was later cut as noise) and an honest "Showing: your Keep-Source look" label. Explicitly an ESTIMATE (Word rewraps in the destination font); a LAYOUT wrapper only — the `tableToHtml`/`renderPivotTree` pipeline + scoped per-level `<style>` are untouched | Done |
| **Command palette (Ctrl/Cmd+K)** | `components/CommandPalette.tsx` — a fuzzy launcher (case-insensitive subsequence match, grouped by section, full keyboard nav, shortcuts as kbd chips) over the existing handlers (Add table, Copy section, Duplicate/Remove section, Undo/Redo, Document settings, Clear all, and a Go-to-section entry per table). Keyboard-only (a "⌕" top-band button existed and was cut as visual noise); portals to `<body>` reusing the Popover backdrop/Escape idiom; no dependency | Done |

## Removed (was built, then cut to focus on pivot)

- The other three layouts: **Grouped by field**, **Fields as bullets**, **A/B/C/D sections** (with `lib/numbering.ts`, the `Section`/`Subsection`/`Body` model, `rowsToTree`/`rowsToAttributeSections`/`rowsToGroupedSections`, `renderTree`/`renderBody`).
- **Download for Word** / **Download all** (`.doc` export) — clipboard-only now.
- **Raw JSON view** (`components/JsonPreview.tsx`) — a third preview tab showing the parsed Grid as JSON. Cut: it showed nothing a developer couldn't get from devtools. The right pane is now **Preview | Table**.
- **Field drag-and-drop, v1 (indent/stack via drop)** — a ⋮ handle + gap drop-zones over one `placeColumn` reducer that could also indent and stack. Deliberately REVERTED as ambiguous (drop-between-vs-into). Superseded by the opt-in **vertical-only** drag preference (see the Done table): `reorderField` keeps the indent skeleton fixed, arrows stay the default, and rail reordering still uses drag-and-drop.
- **Document-wide Body font + Label separator controls** (⚙ Document) — removed on feedback ("don't need whole document font control"): the base font is fixed at Aptos 11 with per-level pins in each Look popover, and label separators became per-level free text in the Body Text Definition matrix (`labelSeps`).
- **Workspace backup Export/Import** (⚙ Document → Backup; `exportWorkspace`/`handleImportFile`) — a whole-workspace `.json` download/restore. Cut as popover clutter (mentor feedback): auto-save already persists the workspace locally, and the **Style preset** covers the real cross-document need (replaying formatting).
- **Arrangement reuse** (`headerSignature` + a “headers match — reuse its arrangement?” banner) — one-click reapplication of a same-shaped section's column-indexed arrangement. Removed with the other ingest assists (mentor feedback: pastes should land blank); the level-keyed **style preset** now carries the recurring-report workflow.
- **Smart Arrange (auto-pivot on paste)** (`lib/smartArrange.ts`) — a cardinality/numeric heuristic that auto-placed EVERY column into a proposed outline the moment a table landed. Removed on mentor feedback: pre-placing all columns front-loaded a structure the user had to unpick, contradicting the deliberate add-field-one-by-one flow. Paste lands blank again; the style preset carries the recurring-report workflow.
- **Docker packaging** (`Dockerfile`, `docker-compose.yml`, `next.config.ts` `output: "standalone"`) — removed as unused; the single-file build covers distribution.
- **`next/font` (Geist Sans + Mono)** — loaded but referenced by no rule; dropped for the system stack (Segoe UI / Cascadia Code), which also keeps the single-file build self-contained.

## Possible next steps

- **In-app paste-mode (Use Destination Styles) preview toggle** — the living page preview shows the *Keep Source Formatting* look (labeled as such); a switch to preview the destination-template Heading look a *Use Destination Styles* paste produces is still future.
- **Precise multi-page cut** — the page preview's pagination is a **best-effort ESTIMATE** (measured from this preview's layout, but Word rewraps in the destination font, so a real break can shift); an exact, guaranteed page split (or a true per-page export) remains out of scope for now.
- **Pivot aggregation** — counts/sums per group (e.g. `Brazil (3)` or a totals summary).
- **Per-table heading styling** — currently styling is global; per-table would need per-instance class scoping or inline styles.
- **`.docx` export** (currently out of scope).
