# Roadmap

The app is **pivot-only**: paste → nest → render → **Copy section**. It began with four view modes and a Download option; those were removed to focus on the pivot. Status of the current feature set below.

| Step | What | Status |
| ---- | ---- | ------ |
| **Data model** | `PivotNode { lines: PivotLine[], children }`, `PivotLine { col, name, value }`, `FieldLabel` ([`lib/types.ts`](../lib/types.ts)) | Done |
| **Paste → raw rows** | SheetJS clipboard parse + JSON preview ([`lib/parser.ts`](../lib/parser.ts)) | Done |
| **Pivot mapper** | `rowsToPivotTree(rows, levels, sortDirs?)` — ordered indent buckets; each bucket is one level of ≥1 field merged by a composite key; a post-pass reorders sibling groups per `sortDirs` ([`lib/mapper.ts`](../lib/mapper.ts)) | Done |
| **Structure picker** | Add-fields pool + the merged **Rows** canvas (one row per field; Windows-Explorer-style tree connector lines │ ├ └ to show nesting) with ◄ outdent / ► indent / ✕ remove buttons PLUS drag-and-drop and ⋮-handle arrow keys (see the "Merged Rows canvas" row) (`pivotLevels: number[][]`) | Done |
| **Depth cap (9 levels)** | The builder caps indent depth at `MAX_LEVELS = 9` (the most Word renders): `canIndent` requires `levels.length < 9`, and `addField` stacks a new field into the deepest level past the cap; a live **N/9 levels** chip (muted → amber at 9 → red over 9) + at-/over-cap warning in the Structure sub-header. 9 is the real ceiling — the renderer clamps `data-level` at 9, `RenderedPreview` builds 9 level rules, and `buildWordHtml` matches only `data-level`/`data-heading` 1–9, so the builder can't diverge from the preview/Word output | Done |
| **Per-field label format** | Per-field toggles (`fieldLabels`): show/hide the `Field name:` label, bold it, underline it (label-only emphasis) | Done |
| **Per-column sorting** | Per-field ↕/↑/↓ cycle (`sortDirs: Record<col, "asc"|"desc">`) orders the sibling groups at that field's level; numeric + text aware, case-insensitive (`localeCompare`, `numeric:true`); off keeps first-seen order | Done |
| **Markers** | A 3-mode dropdown (**Off** = none / **Custom** = per-level SPLIT selects — a **Type** (`1/a/A/i/I/•/–/None`) × an **After** delimiter (`./)/none`), so any counter × delimiter is reachable and the delimiter disables for symbol types / **Multilevel numbers**; default Custom); stored as `markerSpecs: {type, delim}[]`, migrated on read from the legacy fused `markers: MarkerKind[]` via `resolveMarkerSpecs`; in Custom the first field of a multi-field level is marked, restarting per parent | Done |
| **Blank line between top-level groups** | A single on/off checkbox beside the Markers control (`breakAfter` = `[true]`/`[]`, no longer per-level); when on, a nbsp spacer paragraph follows each top-level group's whole subtree (survives a Word paste; no marker/number/label) | Done |
| **Title heading** | Optional Section title → the chosen Word `Heading 1–4` at the correct outline level, emitted as a real `<hN>` element with a full declared source look (adopts the destination heading cleanly in blank docs AND templates on a Use-Destination-Styles/default paste; level threaded as `titleLevel` via `headingLevel(name)`; a non-built-in style name falls back to the `mso-style-name` class route, now first-class via the dropdown's **Custom style…** text input — map the title to any destination style, e.g. `TBL_TITLE`); the title's font/size/color ride inline and its weight lives in its style rule (no inline `font-weight` — bold is an OOXML toggle and the old inverted trick pasted backwards under KSF), so a Keep-Source-Formatting paste matches the preview exactly while a Use-Destination-Styles paste takes the destination heading's complete look + number/outline (COM-verified) | Done |
| **Multilevel numbering (app-drawn static numbers)** | Per-table `numbering: { mode, start, levels }` (the Markers control's **Multilevel** mode; `mode: "off"|"custom"|"multilevel"`) prefixes each node's first line with a static number from a chosen `start` (a dotted-decimal string = the exact first item number; `5.1` → `5.1.1` → `5.1.1.1`) as plain body text and suppresses that node's marker; a per-level checkbox (`numbering.levels`) hides a level and makes it transparent, so the numbers follow the gap (`5.1` → `5.1.1`, `5.1.2`) with no gaps or collisions. NOT Word auto-numbering — nothing becomes a Word heading, so the Nav pane / TOC stay clean and the preview shows the real numbers | Done |
| **Word heading rows** | `headingLevels: boolean[]` (per level, labelled by field name) maps a level's rows to a destination `Heading K` style — emitted as real `<hK>` elements (K ≤ 6) whose rule declares the level's full look, so a Use-Destination-Styles/default paste adopts the destination heading cleanly (blank docs AND templates) and a Keep-Source-Formatting paste shows the preview's bold heading look (KSF never maps named styles); nav pane + collapsible, flush-left; Word numbers them so the app number/marker is suppressed there (the path still computes, so deeper rows nest). K is contiguous by default (checked levels rank in order under the title — no skipped ranks) with an optional per-level pin (`headingRanks`, Auto/H1–H9 chip-dropdown, amber when a pick skips a rank). Scoped to the top level or two, so the nav stays clean | Done |
| **Renderer** | `renderPivotTree(nodes, title?, markers?, fieldLabels?, breakAfter?, numbering?, headingLevels?, titleLevel?, pageBreakBefore?)` → HTML fragment ([`lib/renderers.ts`](../lib/renderers.ts)) | Done |
| **New page per group** | A per-table `pageBreakBefore` checkbox beside the Markers control starts each top-level group (after the first) on a new Word page: the renderer marks that group's first line `data-break="1"`, `buildWordHtml` emits `page-break-before:always` (inline, so it survives a Use-Destination-Styles paste; also works when the row is a Word heading), and `RenderedPreview` shows a dashed page-break rule | Done |
| **Ingest cleanup** | `dropEmptyColumns(grid)` strips fully-blank spacer/padding columns on paste (automatic, no UI) before `newTable`, so they never clutter the Add-fields pool; a header-only (blank-data) column is kept | Done |
| **Header row offset** | Optional `TableState.headerRow` + `bodyGrid(t) = grid.slice(headerRow)` (used by the mapper, the field list, and the page-count stat) skips banner/title rows above the real header. The in-view **Header row** select was REMOVED by request — the field survives as legacy (a stored offset is still honored on read; there is no UI to set it) | Removed (UI) |
| **Arrangement reuse** | Pasting a table whose effective header names match an already-arranged section (`headerSignature`, order-sensitive) offers a one-click banner to reuse that section's arrangement — `pivotLevels`/`markerSpecs`/`fieldLabels`/`sortDirs`/`breakAfter`/`numbering`/`headingLevels`/`headingRanks`/`pageBreakBefore`, never the grid/title/`headerRow` — as one undo step (the recurring-report workflow) | Done |
| **Copy shortcut** | **Ctrl/Cmd+Enter** copies the active section from anywhere (pairs with paste-anywhere); the level owner's Heading rank chip-dropdown shows the resulting **H1/H2… chip** and a *Word numbers* note replaces a heading level's marker control | Done |
| **Clipboard output** | `text/html` (+ `text/plain`) for Word ([`lib/clipboard.ts`](../lib/clipboard.ts) `buildWordHtml`) | Done |
| **Multiple tables + Sections rail** | Paste appends a table; rows in a left Sections rail within a 4-pane IDE layout (cap 100) | Done |
| **Duplicate a section** | `duplicateTable(id)` deep-clones a section (`structuredClone`, fresh id) right after the original and makes it active — for several near-identical tables (same headers, different month/region); a hover **⧉** button on each rail row (`SectionsRail` `onDuplicate`) | Done |
| **Shared per-level styling** | The per-depth nested-row look (color swatch + an **Aa▾** popover: font / size / **B** / **I** / **U**) is edited inline in the Rows canvas's **Look** control on each level's first field (global by depth, badged *All tables*) via the shared `LookControl` component — the IDENTICAL control that styles the Section Title, so "the same thing looks the same"; italic/underline emit as `<i>`/`<u>` runs on the body `<p>`. Only the document-wide **Body font**, **Line spacing**, **Label separator**, **Indent/level**, and **Reset levels** sit in a compact **⚙ Document** popover in the top command band; a shared dependency-free `Popover` (`components/Popover.tsx`) backs both the Look and Document popovers. `PasteInput` owns the state, passes a slimmed `appearance` prop (`{ levelStyles, onLevelChange, bodyFont }`) → `HeadingStyle = { levels: LevelStyle[] }` (per-depth look, color/font/size/bold each) + one Body font + indent step, and drives body font / indent / reset itself; an untouched level's font INHERITS the Body font (`""` = inherit, Look popover pins), so the Body font control actually drives the body in both preview and paste; the popover also carries **Line spacing** (`HeadingStyle.lineSpacing`, 1/1.15/1.5 → `line-height:N%` in preview + paste) and the **Label separator** (`labelSep`, allow-listed, threads `tableToHtml → renderPivotTree → wrapLabel`); `LevelInput`/`DEFAULT_LEVEL` in `tableModel.ts`, `FONTS` exported from `TableCard` | Done |
| **Per-section export** | **Copy section** — copies the active section as its OWN standalone Word doc (clipboard `text/html` + `text/plain`); sections are independent documents, not stacked. (Replaced the old combined "Copy all".) | Done |
| **Malformed-paste handling** | Graceful empty/parse-error states | Done |
| **Session persistence** | The whole workspace (every `TableState` + shared styling) auto-saves to `localStorage` (versioned key, [`lib/persistence.ts`](../lib/persistence.ts)) — debounced + flushed on tab-hide, rehydrated on mount (id counter re-seeded). Local-only; nothing uploaded | Done |
| **Live preview** | The pinned right pane always previews the **active section** — the same `tableToHtml` fragment Copy section writes, so preview and export can't diverge. *(The former This section / All sections combined-preview toggle was removed along with combined export; `RenderedPreview` still accepts a `sections?: string[]` prop but the app no longer passes it.)* | Done |
| **Copy-section confirmation** | After **Copy section**, a visible + `aria-live` banner reads **Section copied.** and the decisive Word paste step (**Keep Source Formatting** vs **Use Destination Styles**, the latter only when a heading is mapped); friendly failure + “add fields first” states | Done |
| **Reorder sections** | **Drag-and-drop** rows in the Sections rail ([`components/SectionsRail.tsx`](../components/SectionsRail.tsx); native HTML5 DnD, with a grip ⋮ + keyboard ↑/↓ as the accessible path) — `onReorder(from, to)` splice-moves `tables[]` (handler `moveTable`). Each section is its own standalone Word document | Done |
| **Undo / redo (all changes)** | Full workspace undo/redo — an effect observes the `SessionSnapshot` memo and records a step on any meaningful change (all fields except pure `activeId` selection), coalescing rapid bursts (typing, color-drag) via a short debounce; two-stack model with `Ctrl+Z` / `Ctrl+Y` and persistent toolbar buttons. Covers reorder, fonts, bold, indent, markers, title, add/remove/duplicate/clear/import. **Clear all** is still a two-step inline confirm | Done |
| **First-run activation** | Onboarding empty state (value prop + 1-2-3 steps + an **Add a table** hero → the intake modal, whose Try-an-example loads `makeExampleTable`) and **paste-anywhere** (a window `paste` listener ingests a copied table unless a text field is focused, so nothing needs focus) | Done |
| **Merged Rows canvas + field drag-and-drop** | The former Structure tree + per-level matrix (which listed every level name twice) are now ONE **Rows** list — one row per field. Per-level controls (Marker/heading/Look) render on the level OWNER (first field of a bucket); a stacked sibling shows a muted "shares level N" note; each field name is a live micro-preview in its level's real look with a sample value. Native HTML5 **drag-and-drop** — a ⋮ handle on every row + the Add-fields chips — drops ONTO a row to stack, or into a GAP to make a new level, via one pure reducer `placeColumn(levels, col, target)` (`newLevelBefore`/`newLevelAfter`/`newLevelEnd`/`stackWith`, `MAX_LEVELS`-capped like `addField`, targets keyed by a stable reference column); the ⋮ handle's ArrowUp/Down (`moveField`) + ArrowLeft/Right (indent/outdent) are the keyboard twin (the ▲▼ buttons folded into the handle; ◄ ► ✕ remain). Delivers the roadmap's #1 simplicity win AND the deferred field DnD together; level styles stay GLOBAL-by-depth | Done |
| **Add-table modal + client-side file ingest** | A ＋ Add-table modal ([`components/AddTableModal.tsx`](../components/AddTableModal.tsx)) previews what it read before committing: **intake** (paste / file drop / Browse `.xlsx`·`.xls`·`.csv`·`.tsv` / Try-an-example) → **preview** ("Read N × M" + mini-table + Add section / Clear). Files parse fully client-side via `parseFile` (`XLSX.read(arrayBuffer, { type: "array" })`, the same SheetJS, shared `firstSheetToGrid` helper) — no new dependency. `onCommit(grid)` routes to the existing `ingestGrid`; retires the old inert `pasteZone`; paste-anywhere still works (the modal's window listener + `addModalOpenRef` guard prevent double-ingest) | Done |
| **Smart Arrange (auto-pivot on paste)** | `smartArrange(grid)` ([`lib/smartArrange.ts`](../lib/smartArrange.ts)) proposes a nested `pivotLevels` from a fresh grid so a paste lands already-outlined: profiles columns (cardinality + numeric/currency detection), classifies **group** (own indent level, kept in ORIGINAL column order) / **measure** (numeric → stacked deepest) / **detail** (near-unique text → stacked deepest), caps at `MAX_LEVELS`, returns `null` when nothing to propose. Wired into `ingestGrid` with explicit PRECEDENCE: an exact-header arrangement-reuse match wins; else it applies with a dismissible "Auto-arranged into N levels — Start blank" banner (one undo step). Deliberately no functional-dependency detection (per design review) | Done |
| **Living Word-page preview** | `RenderedPreview` renders on a true-to-scale US-Letter proxy — a proportional 1in-margin frame (~6.5in text column) with MEASURED, best-effort pagination (ref + `ResizeObserver` → a dashed "Page N" boundary every 9in usable band + a green "Fits 1 page" / amber "~N pages (estimate)" chip) and an honest "Showing: your Keep-Source look" label. Explicitly an ESTIMATE (Word rewraps in the destination font); a LAYOUT wrapper only — the `tableToHtml`/`renderPivotTree` pipeline + scoped per-level `<style>` are untouched | Done |
| **Command palette (Ctrl/Cmd+K)** | `components/CommandPalette.tsx` — a fuzzy launcher (case-insensitive subsequence match, grouped by section, full keyboard nav, shortcuts as kbd chips) over the existing handlers (Add table, Copy section, Duplicate/Remove section, Undo/Redo, Document settings, Clear all, and a Go-to-section entry per table). A "⌕" top-band button surfaces it; portals to `<body>` reusing the Popover backdrop/Escape idiom; no dependency | Done |

## Removed (was built, then cut to focus on pivot)

- The other three layouts: **Grouped by field**, **Fields as bullets**, **A/B/C/D sections** (with `lib/numbering.ts`, the `Section`/`Subsection`/`Body` model, `rowsToTree`/`rowsToAttributeSections`/`rowsToGroupedSections`, `renderTree`/`renderBody`).
- **Download for Word** / **Download all** (`.doc` export) — clipboard-only now.

## Possible next steps

- **In-app paste-mode (Use Destination Styles) preview toggle** — the living page preview shows the *Keep Source Formatting* look (labeled as such); a switch to preview the destination-template Heading look a *Use Destination Styles* paste produces is still future.
- **Precise multi-page cut** — the page preview's pagination is a **best-effort ESTIMATE** (measured from this preview's layout, but Word rewraps in the destination font, so a real break can shift); an exact, guaranteed page split (or a true per-page export) remains out of scope for now.
- **Pivot aggregation** — counts/sums per group (e.g. `Brazil (3)` or a totals summary).
- **Per-table heading styling** — currently styling is global; per-table would need per-instance class scoping or inline styles.
- **`.docx` export** (currently out of scope).
